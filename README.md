# Embody —— 给 AI 一个身体

> 从一只会说话的桌面小黄鸭开始，分阶段造出一个能动、能看、能和真实世界互动的 AI 实体。

这是一个**人机协作**的硬件 + 软件项目：

- **AI（Claude）** 负责：系统架构、软件设计与实现、固件、通讯协议、硬件选型与 BOM、机械结构建议、测试方案。
- **人（Will）** 负责：采购元件与开发板、3D 打印 / CNC / 组装、接线、烧录、现场测试并把观察结果反馈回来。

项目的核心思想是**分层**：大语言模型不适合做 50 Hz 的电机控制，微控制器也跑不了大模型。所以身体被拆成三层——
云端 **大脑**（推理、对话、规划）、边缘 **小脑**（感知、低延迟决策）、单片机 **脊髓**（实时控制、反射、安全）——
每一层只做它擅长的事，层与层之间用明确的协议连接。详见 [`docs/02-architecture.md`](docs/02-architecture.md)。

## 技术瓶颈一览

硬件、软件、网络三条线各自的限制和我们的应对，集中写在 [`docs/03-constraints.md`](docs/03-constraints.md)。最重要的几条：

1. **延迟**：语音往返（ASR + LLM + TTS）天然要 1–3 秒，必须靠流式处理和"先动作、后说话"来掩盖。
2. **算力分层**：ESP32 跑不了任何大模型，树莓派 5 只能跑很小的模型，真正的推理在云端；网络一断，身体必须还能安全地"活着"。
3. **电池与执行器**：能动的东西里，电机 / 舵机 / 电池是重量、成本、发热的大头，机械设计围着它们转。
4. **网络抖动**：Wi-Fi 延迟 20–200 ms 且不稳定，任何需要实时闭环的控制都不能跨网络。

## 仓库结构

```
docs/        规划、架构、约束、每个阶段的详细方案
hardware/    每个阶段的 BOM、接线图、3D 模型（STL/STEP）、PCB
firmware/    单片机固件（ESP32 系列，ESP-IDF / PlatformIO）
edge/        边缘端（树莓派 / Jetson）的感知与控制服务（Python）
embody/      Python 包：proto（协议）、cloud（云端大脑）、sim（软件鸭）
```

## 开发

M0 阶段（软件鸭）的安装、启动、调试和延迟日志说明见 [`docs/05-m0-dev-guide.md`](docs/05-m0-dev-guide.md)。最常用的三条命令：

```bash
pip install -e ".[dev]"                      # 安装（先 python3 -m venv .venv && . .venv/bin/activate）
embody-cloud                                 # 启动云端大脑（需要 ANTHROPIC_API_KEY）
embody-duck --url ws://127.0.0.1:8765/ws     # 启动软件鸭
```

## 协作方式

1. 每个阶段开始前，AI 在 `docs/` 写方案和 BOM，人确认预算和可采购性。
2. 人采购、组装；每一步拍照 / 记录现象，回填到对应阶段文档的「实测记录」小节。
3. AI 根据实测迭代固件和软件；问题用 GitHub Issue 跟踪。
4. 阶段退出条件全部满足 → 打一个 tag（如 `phase0-done`）→ 进下一阶段。
