# 03 · 技术瓶颈与限制

这一页回答"为什么不能一步到位"。每条限制后面跟着我们的应对，以及它影响的阶段。

---

## A. 硬件

### A1. 单片机算力：ESP32 跑不了任何"智能"

- ESP32-S3：双核 240 MHz、512 KB SRAM（+ 8 MB PSRAM 可选）、无浮点向量单元可言。
- 能做：Opus 编解码、WebRTC 级 AEC/VAD、唤醒词（ESP-SR，几十 KB 的模型）、PID、动画。
- 不能做：任何 LLM、ASR（除了超小词表的命令词）、实时视觉（最多 QVGA 抠一个颜色块）。
- **应对**：阶段 0–1 把智能全放云端；阶段 2 加边缘板。MCU 永远只做实时与安全。

### A2. 边缘算力：树莓派够"看"，不够"想"

| 板子 | 算力 | 功耗 | 能跑什么 | 价格 |
|---|---|---|---|---|
| 树莓派 5 (8 GB) | CPU only，无 NPU | 5–10 W | 流式 ASR（sherpa-onnx int8）、YOLO-n 级检测 10–20 fps、1–3B 量化 LLM 约 2–5 tok/s（勉强） | ~¥600–700 |
| 树莓派 5 + AI HAT+ (26 TOPS) | Hailo-8 | +3 W | 检测 / 分割类模型跑得很好；不帮 LLM | +¥500–700 |
| Jetson Orin Nano Super 8 GB | 67 TOPS, 102 GB/s | 7–25 W | 3–8B 量化 LLM 10–20 tok/s、小型 VLM、VLA 策略推理 | ~¥1800–2500 |

- 结论：**对话智能留在云端**，本地只放"必须低延迟或必须离线"的部分（唤醒、VAD、检测、跟随、安全）。
- 边缘板是整机耗电大户，上它之前先把电池方案做大（阶段 2 的电源重新设计）。

### A3. 执行器：舵机便宜但粗，好电机贵且重

- SG90 / MG90S 微型舵机：¥5–15，精度 ±1–2°，有回差、有噪声、堵转容易烧。适合阶段 0 的点头 / 扑翅。
- 总线舵机（Feetech STS3215 等）：¥80–150 一个，带位置 / 力矩反馈，是阶段 3 机械臂的下限。
- N20 减速电机：¥10–30，低速扭矩有限，带编码器的版本做里程计。
- 任何能动的身体，**执行器 + 电池 ≈ 60% 的重量和 50% 的成本**，机械设计围着它们转。
- **应对**：阶段 0 用最便宜的舵机验证表现力，阶段 1 只用 2 个电机，阶段 3 才上总线舵机。

### A4. 电池与功耗

- 18650 锂电约 10 Wh / 节；ESP32 + 喇叭 + 2 舵机空闲 ~0.5 W、说话 ~2 W；加 2 个 N20 运动 +2–4 W；加树莓派 5 +5–10 W。
- 结论：阶段 1 两节 18650 够跑 3–5 小时；阶段 2 要 3S 或更多，并且散热变成问题。
- 锂电安全：必须有保护板、过放保护、充电管理；3D 打印外壳里不要让电池贴着发热元件。
- **应对**：阶段 0 直接 USB 供电，不碰电池；阶段 1 用成熟的充电宝模块或带保护板的电池组。

### A5. 音频前端：回声消除决定能不能"打断"

- 喇叭和麦克风装在同一个小壳子里，麦克风听到的喇叭声比人声大得多。没有 AEC，鸭子说话时听不到你。
- 软件 AEC 在 ESP32 上能跑（ESP-SR），但需要喇叭参考信号同步，自己搭的板子对不齐时钟很痛苦。
- **应对**：阶段 0 首选自带硬件 AEC 参考通道的方案（ESP32-S3-BOX-3）；自己搭则接受"说话时不能打断"作为降级。

### A6. 传感器：便宜的只能"知道有东西"，贵的才能"知道是什么"

- ToF（VL53L0X）：¥10–20，2 m 内测距，窄视角，只能做避障。
- 单目摄像头：便宜，但没有深度，抓取 / 导航都难。
- 深度相机（OAK-D Lite / RealSense）：¥700–2500。
- 激光雷达（RPLIDAR C1）：¥400–600，室内 SLAM 的起点。
- 触觉 / 力觉：目前没有便宜又好的方案，阶段 3 用舵机电流代替力反馈。
- **应对**：每个阶段只加当阶段任务必需的传感器。

### A7. 制造：3D 打印的限制

- FDM 打印件精度约 ±0.2 mm，配合面要留 0.2–0.4 mm 间隙；小舵机的卡槽要可调。
- 薄壁（< 1.2 mm）易裂，悬臂 / 大平面易翘。鸭壳分两件、底座可拆是为了方便维修而不是好看。
- 需要强度的件（阶段 3 机械臂）用 PETG / 尼龙或 CNC 铝件。

## B. 软件

### B1. LLM 不能做控制器

- 一次 LLM 调用 0.5–3 s，而电机控制需要 10 ms 级反馈。LLM 发"过来"，走过去的过程它根本不参与。
- LLM 输出有随机性，不能用于任何安全相关的判断。
- **应对**：Body API 只暴露高层意图；闭环控制与安全约束全部在 MCU / 边缘，LLM 的指令被当作"建议"校验后执行。

### B2. 延迟是产品体验的第一瓶颈

- 详见 [`02-architecture.md` §4](02-architecture.md)：天然 1.2–3 s，无法消除，只能掩盖。
- **应对**：全链路流式；先动作再说话；prompt cache；短 system prompt；TTS 首句短。

### B3. 语音识别在真实环境里会崩

- 距离 > 2 m、有电视声、鸭子自己的电机噪声，识别率断崖式下降。
- 中英混说、人名、口语化的省略，云 ASR 也经常错。
- **应对**：近场使用为主；电机运动时降低 ASR 置信度 / 暂停识别；阶段 2 用唤醒词过滤。

### B4. 记忆与人格的一致性

- 上下文窗口有限，长期记忆要显式存取，"记住你喜欢什么"需要工具而不是靠模型自己记。
- 性格通过 system prompt 维持，但模型在长对话中会漂。
- **应对**：`remember/recall` 工具 + 每轮注入人格摘要；对话窗口按轮数截断。

### B5. 视觉与操作模型还不成熟（阶段 2–3）

- 通用 VLM 能描述场景，但给不出可执行的空间坐标；VLA（视觉-语言-动作）模型需要大量演示数据、对场景变化敏感、推理算力要求高。
- 模仿学习（ACT / Diffusion Policy）在固定场景 50–200 次演示可用，换桌布就可能失效。
- **应对**：阶段 3 任务收窄到固定场景、少量物体；接受 70% 成功率作为目标；sim-to-real 先不碰。

### B6. 固件开发迭代慢

- 每次改固件要编译、烧录、重启，排错靠串口日志；ESP-IDF 的坑不少（内存碎片、任务饿死、Wi-Fi 与 I2S 抢 DMA）。
- **应对**：固件只放稳定的实时逻辑，所有"策略"放云端 / 边缘热更新；OTA 从第一天就有；软件鸭让大部分逻辑在电脑上先跑通。

### B7. 安全

- 能动的东西会夹手、掉落、烧舵机。
- **应对**：MCU 级限位与超时；运动指令最大位移 / 速度上限；悬崖检测；物理急停（阶段 3 必须有按钮）；低电 / 过温自动停。

## C. 网络与通讯

### C1. Wi-Fi 延迟与抖动

- 家用 2.4 GHz Wi-Fi：RTT 典型 5–30 ms，拥塞时 100–300 ms，偶发 1 s 以上的丢包。ESP32 只支持 2.4 GHz。
- 所以**任何 100 ms 级的闭环都不能跨 Wi-Fi**——这是分层架构的根本原因。
- **应对**：200 ms 音频抖动缓冲；运动指令在 MCU 本地闭环；心跳 3 s 判断断线。

### C2. 到云端 LLM 的往返

- 到 API 服务器的 RTT 100–300 ms（取决于地理位置与链路），加上流式生成本身。
- 如果设备所在地访问 API 需要经过中转，延迟会再加 100–500 ms 且不稳定。
- **应对**：云端大脑先跑在家里一台电脑 / 小主机上，由它统一对外请求 API，设备只连局域网；把复杂链路问题收敛到一个点。

### C3. 带宽

- 上行 Opus 语音 32 kbps：任何网络都够。
- 视频：640×480 MJPEG 15 fps 约 2–4 Mbps，持续上传会把家庭上行吃光、也烧 API 费用。
- **应对**：永远不向云端推视频流。边缘板做检测，只在需要时上传一张关键帧（阶段 1 的 ESP32 摄像头同理）。

### C4. 蓝牙不是主通道

- BLE 实际吞吐约 100–500 kbps、连接距离短、Android/iOS 行为不一致。适合配网和近场调试，不适合音频。
- **应对**：BLE 只用于首次配网（把 Wi-Fi 密码传给鸭子）和手机端调试。

### C5. 蜂窝（4G/5G）

- 模块 ¥100–300、功耗 1–2 W、月租；对一只家里的鸭子没有必要。
- **应对**：阶段 4 走出家门再考虑。

### C6. 断网必须是"正常状态"

- 路由器重启、Wi-Fi 切换、云端维护，都会发生。断网时鸭子如果变成一块砖，体验就毁了。
- **应对**：离线人格（MCU 本地脚本）；运动中断网 500 ms 内停；自动重连带指数退避；边缘板到位后本地唤醒 + 本地 ASR 做部分离线对话。

### C7. 安全与隐私

- ESP32 上跑 TLS 可行但吃内存（每条连接 ~40 KB），证书要可更新。
- 麦克风常开上传是隐私问题。
- **应对**：设备预共享 token 认证（阶段 2 换 mTLS）；OTA 固件签名校验；阶段 2 起本地唤醒词，不唤醒不上云；有物理静音开关或指示灯。

## D. 一句话版本

> 大模型在云端，反射在单片机，中间用 Wi-Fi 传"意图"不传"控制"；
> 不动的身体先把语音链路和断网降级做扎实，再给它轮子，再给它眼睛，最后给它手。
