# 01 · 阶段路线图

每个阶段回答四个问题：**造什么、为什么是这个顺序、要买什么、做到什么算完成**。
阶段之间不是"推翻重来"，而是**叠加**：阶段 0 的 ESP32 板子到阶段 2 还在用，只是从"大脑"降级为"脊髓"。

---

## 阶段 0 · 桌面小黄鸭（不会动的身体）

**目标**：验证"语音 → 云端 LLM → 语音 + 动作"这条最短闭环，并把延迟、协议、OTA、断网降级这些基础设施一次搞定。
它不会走，但它会：听你说话、用自己的性格回答、点头 / 摇头 / 扑腾翅膀、眼睛变色表达情绪、被摸头会有反应。

**为什么先做它**

- 不动的东西没有安全问题，可以放心迭代软件。
- 一只鸭子能暴露 80% 的系统问题：音频链路、回声消除、Wi-Fi 稳定性、LLM 工具调用、流式 TTS、OTA。
- 预算低，一两周能看到成品，建立节奏。

**硬件（详见 [`04-phase0-duck.md`](04-phase0-duck.md) 与 [`../hardware/phase0/BOM.md`](../hardware/phase0/BOM.md)）**

- 主控：ESP32-S3（推荐 ESP32-S3-BOX-3 整机，或 Seeed XIAO ESP32S3 Sense 自己搭）
- 音频：双麦 + I2S 功放 + 2–3 W 喇叭；最好有硬件回声消除（AEC）
- 执行：2 个微型舵机（头部俯仰、翅膀），1 圈 WS2812 RGB LED（眼睛 / 腮红）
- 传感：电容触摸（头顶）、可选 6 轴 IMU（被拿起来会知道）
- 电源：USB-C 5 V 供电，先不上电池
- 外壳：3D 打印两件式鸭壳 + 可拆底座

**软件交付**

- `sim/`：软件鸭（M0）
- `firmware/duck/`：Wi-Fi 配网、WebSocket、Opus 音频流、舵机 / LED 动画状态机、OTA、断网离线人格
- `cloud/`：WebSocket 网关、ASR → Claude（tool use，流式）→ TTS 编排、Body API 工具定义、基础记忆
- 延迟仪表：每轮对话输出 ASR / 首 token / 首音频块 / 网络各段耗时

**退出条件**

- [ ] 连续对话 30 轮不掉线、不重启
- [ ] 从说完到鸭子开始发声，P50 < 1.5 s，P95 < 3 s
- [ ] 鸭子能用动作 + 眼色表达至少 6 种情绪，且动作与语音同步感可接受
- [ ] 拔掉路由器，鸭子 2 秒内进入离线人格，网络恢复后 10 秒内自动重连
- [ ] OTA 升级一次成功，失败能回滚
- [ ] 外壳装得进、拆得开，连续运行 1 小时不过热

## 阶段 1 · 会跑的小黄鸭（第一次动起来）

**目标**：加一个两轮底盘和电池，让鸭子能在桌面 / 地板上移动、避障、被叫时转向声源。
**这个阶段真正要学的是**：电机控制、电源管理、以及"LLM 发高层指令、MCU 做低层反射"的分层控制。

**新增硬件**

- 底盘：2 × N20 带编码器减速电机 + TB6612FNG 驱动 + 万向轮
- 感知：3 × VL53L0X / VL53L1X ToF 测距（前 / 左前 / 右前），1 × 6 轴 IMU（MPU6050 或 ICM-42688）
- 电源：2 × 18650 或 1 × 2S 锂聚合物 + 保护板 + 5 V 降压 + 充电管理（或直接用带 PD 的充电宝模块）
- 可选：悬崖检测（朝下的红外对管），防止从桌边掉下去
- 可选：ESP32-S3 自带摄像头接口接 OV2640，先做低分辩率"看一眼"

**软件交付**

- MCU：轮速 PID、里程计、ToF 避障反射（不经过云端）、悬崖急停、低电保护
- Body API 新增工具：`move(distance, speed)`、`turn(angle)`、`follow_sound()`、`stop()`
- 云端：声源方向（双麦相位差，粗粒度）→ 转向
- 安全：任何运动指令带超时与最大位移；MCU 对云端指令做可行性校验

**退出条件**

- [ ] 桌面上随机移动 10 分钟不掉落、不撞东西
- [ ] 说"过来"，鸭子转向说话人并前进到 30 cm 内停下
- [ ] 一次充电连续待机 ≥ 4 小时，边聊边动 ≥ 1.5 小时
- [ ] 网络中断时正在移动的鸭子 500 ms 内停下

## 阶段 2 · 有眼睛的伙伴（加边缘算力）

**目标**：加一块树莓派 5 或 Jetson Orin Nano，把"感知"从云端拉回本地：本地唤醒词、本地流式 ASR、摄像头认人 / 认物、简单的室内跟随。
ESP32 不再是大脑，变成实时协处理器（电机、舵机、传感器采样、安全），通过 USB 与边缘板通讯。

**为什么到这一步才加算力板**

- 前两个阶段用 ESP32 把"云端能做什么、做不到什么"摸清楚了，知道哪些必须本地化。
- 边缘板耗电大（树莓派 5 满载 ~10 W，Jetson Orin Nano 7–15 W），电池和散热方案要在阶段 1 的基础上重新设计。

**新增硬件**

- 边缘板：树莓派 5（8 GB）+ 主动散热，或 Jetson Orin Nano Super 8 GB（如果要跑视觉大模型）
- 摄像头：树莓派 Camera Module 3（广角）或 USB 摄像头；可选深度相机（OAK-D Lite / RealSense D435）
- 麦克风阵列：ReSpeaker 4-Mic 或继续用 ESP32-S3-BOX-3 的双麦
- 显示：1.28 寸圆形 LCD × 2 做眼睛（表现力质变）
- 电源：升级到 3S 锂电 + 更大的降压，或 4 × 21700

**软件交付**

- `edge/`：唤醒词（openWakeWord / Porcupine）、VAD、sherpa-onnx 流式 ASR、人脸检测与识别、物体检测（YOLO 系列）、跟随
- 边缘 ↔ MCU 二进制协议（200 Hz），边缘 ↔ 云端事件协议
- 云端：多模态——把关键帧发给 Claude 看，让它描述场景、认人
- 长期记忆：记住谁是谁、家里布局

**退出条件**

- [ ] 不说唤醒词时麦克风不上云；唤醒识别率 > 95%，误唤醒 < 1 次 / 小时
- [ ] 认出至少 3 个家庭成员并叫名字
- [ ] 室内跟随一个人走 5 分钟不丢
- [ ] 能回答"我手里拿的是什么"

## 阶段 3 · 能拿东西（操作能力）

**目标**：一条低成本 6 轴舵机机械臂（SO-100 / LeRobot 生态），先遥操作采集数据，再做模仿学习，完成"把杯子推过来""捡起积木"这类任务。
**这是从"陪伴玩具"跨到"机器人"的那一步，难度跳跃很大，前面三个阶段的基础设施是为它铺路。**

**新增硬件**

- 机械臂：SO-100 / SO-101（Feetech STS3215 舵机 × 6，3D 打印结构件），约 ¥800–1500 一条；遥操作需要主从两条
- 腕部摄像头 + 固定第三视角摄像头
- 算力：Jetson Orin Nano 本地推理，或训练在云端 GPU、推理在本地

**软件交付**

- 遥操作、数据录制（LeRobot 格式）、ACT / Diffusion Policy 训练流程
- Body API 新增高层工具：`pick(object)`、`place(location)`、`push(object, direction)`
- 安全：力矩限制、工作空间围栏、紧急停止按钮

**退出条件**

- [ ] 遥操作完成 50 次抓取演示
- [ ] 训练后的策略在同一场景下成功率 > 70%
- [ ] 语音说"把积木给我"，全链路跑通一次

## 阶段 4+ · 走出桌面（远期）

四足平台、更大的轮式底盘、室内 SLAM 与导航、多机。先不展开，到阶段 2 结束时再根据实际情况规划。

## 时间与预算总览（粗估）

| 阶段 | 硬件预算 | 预计周期 | 关键风险 |
|---|---|---|---|
| 0 | ¥200–500 | 2–4 周 | 回声消除做不好导致打断失败；国内访问 LLM API 链路 |
| 1 | +¥300–500 | 4–6 周 | 电池 / 电源噼里啪啦的各种问题；电机噪声干扰麦克风 |
| 2 | +¥1500–3500 | 8–12 周 | 边缘板功耗与散热；视觉模型效果与延迟 |
| 3 | +¥2000–5000 | 3–6 个月 | 模仿学习数据量与泛化；机械臂精度 |

周期按"业余时间推进"估，全职可以除以 2–3。
